# Миграционные архивы — полный перенос состояния между машинами

Команды `gotr export migration-archive` и `gotr import migration-archive`
позволяют упаковать в один файл и перенести между машинами:

- один снапшот;
- произвольный набор снапшотов;
- **всё содержимое `~/.gotr/`** одной командой.

Применяйте, когда нужно:

- передать результат миграции другому оператору;
- зеркалировать состояние рабочей станции на CI-раннер или коллеге;
- сделать полный архив перед переустановкой системы.

---

## TL;DR

```bash
# На исходной машине: упаковать ВСЁ состояние gotr в один архив
gotr export migration-archive
# → ~/.gotr/exports/all/migration_bundle_all_<N>snaps_<UTC-ts>.tar.gz

# Скопируй файл на целевую машину и:
gotr import migration-archive ~/Downloads/migration_bundle_all_*.tar.gz
# Снапшоты, репорты и логи восстанавливаются под ~/.gotr/, импортированные
# снапы автоматически регистрируются в ~/.gotr/snaps/manifest.json — gotr snap list
# показывает их сразу.
```

---

## Режимы экспорта

| Команда | Что упаковывается | Тип архива | Папка по умолчанию |
|---|---|---|---|
| `gotr export migration-archive` | Все снапшоты + всё дерево `reports/` + всё дерево `logs/` | `migration_bundle` | `~/.gotr/exports/all/migration_bundle_all_<N>snaps_<ts>.tar.gz` |
| `gotr export migration-archive --all` | То же (явно) | `migration_bundle` | `~/.gotr/exports/all/` |
| `gotr export migration-archive --label <substr>` | Снапы, чей `label` содержит подстроку, + объединение их репортов/логов | `migration_bundle` | `~/.gotr/exports/all/migration_bundle_label-<slug>_<N>snaps_<ts>.tar.gz` |
| `gotr export migration-archive <id1> <id2> ...` | Перечисленные снапы + объединение их репортов/логов | `migration_bundle` | `~/.gotr/exports/all/migration_bundle_multi_<N>snaps_<ts>.tar.gz` |
| `gotr export migration-archive <single-id>` | Один снап + его репорты + его ±1ч окно логов | `snap` (одиночный) | `~/.gotr/exports/snaps/migration_<id>_<ts>.tar.gz` |
| `gotr export migration-archive --out PATH` | По выбранному режиму | — | Произвольный путь, перекрывает дефолт |

`--label <substr>` сравнивается **без учёта регистра**.

### Структура архива

В корне `migration_bundle` архива:

```text
manifest.json     — тип, версия схемы, snap_ids, контрольные суммы
SHA256SUMS        — для верификации сторонними утилитами
README.txt        — человекочитаемое резюме
snaps/<id>/...    — по директории на снапшот (полное дерево meta+data)
reports/...       — встроенные репорты (всё дерево ~/.gotr/reports/ при --all)
logs/...          — встроенные логи (всё дерево ~/.gotr/logs/ при --all)
```

Single-snap архив (`Kind=snap`) имеет ту же раскладку, но содержит
ровно одну директорию `snaps/<id>/` и только окно репортов/логов
этого снапа.

## Импорт

### Путь к файлу — обязательный аргумент

```bash
gotr import migration-archive <путь-к-файлу>
```

Аргумент — это **исходный архив**, а не место назначения. Распаковка
**всегда** идёт в системную директорию `~/.gotr/` (или `$GOTR_HOME`,
если задана). Флага «куда импортировать» нет специально: иначе
кросс-машинный перенос терял бы смысл.

В интерактивном режиме (TTY, без `--non-interactive`) и без
аргумента picker сканирует **обе** директории —
`~/.gotr/exports/snaps/` и `~/.gotr/exports/all/` — и предлагает
объединённый список.

### Автоопределение типа

Импорт читает `manifest.json` внутри архива и выбирает путь
восстановления:

- `Kind=snap` → восстанавливает один снапшот. `--rename-id <new-id>`
  можно использовать для разрешения конфликта по ID.
- `Kind=migration_bundle` → восстанавливает все снапшоты из
  `snap_ids`, плюс встроенные репорты и логи. `--rename-id` для
  multi-snap **не поддерживается** (1→N не имеет однозначного маппинга).

### Авто-регистрация в манифесте (с v3.4.0-dev)

После переноса файлов на диск импорт автоматически обновляет
`~/.gotr/snaps/manifest.json`, чтобы каждый импортированный снапшот
был сразу виден `gotr snap list` — без последующего запуска
`gotr snap manifest repair`.

- Без `--overwrite`: новые записи добавляются.
- С `--overwrite`: устаревшая запись с тем же ID удаляется, потом
  добавляется свежая — без дублей.
- Если у конкретного снапа нечитаем `meta.json`, файлы остаются на
  диске, но в манифест запись не попадает; её подберёт следующий
  `gotr snap manifest repair`.

### Прочие флаги

```text
--dry-run         Показать, что будет импортировано, без записи на диск
--overwrite       Перезаписать существующие снапшоты (бэкап в <store>/.trash/)
--rename-id ID    Только single-snap: положить под новым ID
--skip-reports    Не восстанавливать reports/ из архива
--skip-logs       Не восстанавливать logs/ из архива
```

Существующие файлы в `~/.gotr/reports/` и `~/.gotr/logs/`
**никогда не перезаписываются**; они учитываются как `skipped`,
импорт продолжается.

## Где живут архивы

```text
~/.gotr/exports/
├── snaps/    — одиночные snap_<id>_<ts>.tar.gz, migration_<id>_<ts>.tar.gz
├── reports/  — экспортированные репорты (.zip / .pdf / .md / .json)
├── api/      — сырые API-дампы (`gotr export <resource> --save`)
└── all/      — полные/мульти-снап migration_bundle_*.tar.gz (с v3.4.0-dev)
```

Папка `all/` создаётся при первом мульти-снап экспорте. Старые
архивы с предыдущей раскладкой остаются работоспособными — импорт
принимает явный путь к файлу из любого места.

## Проверка переноса

После импорта:

```bash
gotr snap list                          # Импортированные снапы видны сразу
gotr snap manifest repair --dry-run     # Должен показать 0 изменений
ls ~/.gotr/reports/                     # Восстановленные репорты
ls ~/.gotr/logs/                        # Восстановленные логи
```

Для побайтной верификации сравните `SHA256SUMS` из архива с
распакованными файлами на диске.

## Частые проблемы

- **«snap already exists» при импорте.** Используй `--overwrite`
  (старый снап уезжает в `<store>/.trash/`) или `--rename-id` для
  single-snap архивов.
- **`gotr snap list` пуст после импорта на старой версии.**
  Авто-регистрация добавлена в v3.4.0-dev. На предыдущих сборках
  выполни один раз `gotr snap manifest repair`.
- **Репорты/логи не восстановились.** Проверь, не было ли
  `--skip-reports` / `--skip-logs` при экспорте, и попадают ли логи
  в окно снапа. Для безусловного включения используй `--all`.
- **Архив с несколькими снапами оказался в `exports/snaps/`.**
  Поведение до v3.4.0-dev. Файл по-прежнему импортируется из
  любого пути; новые экспорты идут в `exports/all/`.
